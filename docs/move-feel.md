# 駒を指したときの手応えの検討

2026-11-17 に、駒を動かしたときの気持ちよさを調整した。試したことと評価を残す。
実装は `src/ui/boardView.ts` の `animate()`・`impact()`・`softImpact()` と、`src/styles.css` の着地の演出（`.impact-*`・`.board-ripple`）。

## 結論（今の実装）

- 振動（バイブ）は使わない。
- 駒は速く運ぶ。少し持ち上げてから、勢いのまま盤に叩きつける。
- 対局中の着地では、次の演出を同時に出す。
  - 駒が潰れて弾む
  - マスが光る
  - 衝撃の輪が2重に広がる
  - 木くずが飛ぶ
  - 盤全体が揺れる
  - 盤全体に光の波紋が広がる
- 結果画面で手順を1手ずつ送るときは、軽い演出だけにする（連打するとうるさいため）。
- 端末で「視差効果を減らす」を有効にしていると、動き自体を出さない（前からの動作）。

## 演出の段階と駒音（2026-11-17 追加・評価はこれから）

演出研究の知見（効果音の効果が大きい、出来事の重さで強さを変える、結果は段階的に見せる、本当の達成を伝える）をもとに、次のように変えた。

| 段階 | いつ | 演出 | 音（`src/ui/sound.ts`） |
|---|---|---|---|
| 軽 | 玉方の応手 | 駒が軽く潰れ、マスが光るだけ。盤の揺れ・波紋・木くずはなし | 小さめの駒音 |
| 標準 | 自分の手 | 上の「今の実装」のまま | 駒音 |
| 強 | 自分の手で駒を取る・成る | 衝撃の輪を3重にし、木くずを16個・遠くまで飛ばす | 取る：低く重い音。成る：澄んだ響きを重ねる |
| 詰み | 詰ませたとき | 着地で110ms止める（ヒットストップ）→ 玉が震えて沈み、玉のマスが赤く灯り、玉から赤い波紋 → 盤の中央に「詰」の印 → カード | 重い一打と2音の響き |

- 攻方の手はすべて王手なので、王手かどうかでは分けない。正誤が分かってしまうので、手の良し悪しでも分けない（`MIN_REPLY_DELAY_MS` と同じ考え方）。
- 詰みの演出は約0.8秒。盤をタップすれば、終わりを待たずにカードを出す。
- 駒音は Web Audio で合成している（音源ファイルなし）。設定の「駒音を鳴らす」で切り替えられる。振動は使わない。
- 結果のカードに、履歴から言える事実だけを出す（`src/game/feats.ts`）：初見で最短／初見で正解／リベンジ成功／自己ベスト更新／手数ごとの正解数（はじめての1問、N問目）。
- 珍しい達成（9手詰以上を初見で最短、手数ごとの正解数が10・50・100問ごと）では、印・波紋・カードを金色にし、響きを1音足す。

## 試したこと

### 振動（バイブ）：やめた

自分（攻方）が指した手だけ、ごく軽く振動させていた。
`navigator.playHaptics` が使えればそれを使い、なければ `navigator.vibrate(6)` を使っていた。
不快なので、振動そのものをやめた。

### 駒の速度：速くした

| | 元 | 1回目 | 今 |
|---|---|---|---|
| 運ぶ時間（距離で変わる） | 60〜100ms | 45〜75ms | 35〜60ms |
| 取った駒を駒台へ運ぶ時間 | 110ms | 90ms | 80ms |
| 持ち上げる大きさ | 1.04倍 | 1.1〜1.14倍 | 1.08倍 |
| 動き出し | ゆっくり出て加速 | ゆっくり出て加速 | すぐ動き出す |

1回目は「遅い」と言われた。運ぶ時間が短くても、次の2つで遅く見えたと考えている。

- 出だしがゆっくりの加速のさせ方
- 大きく持ち上げる動きと、着地後に長く潰れて弾む動き（200ms）

動き出しをすぐにして、持ち上げを小さくし、潰れて弾む時間を140msに縮めた。

玉方の応手が出るまでの待ち時間（最低320ms、`src/app.ts` の `MIN_REPLY_DELAY_MS`）は変えていない。
エンジンは詰みがあるとすぐに答えを返す。待ち時間を揃えないと、早さで正誤が分かってしまう。

### 着地の演出：強くした

元の演出は控えめだった（駒を50msだけ押しつぶす、盤を1px沈ませる、マスの枠を一瞬光らせる）。
もっと強いほうが気持ちいいという意見で、次の演出に変えた。

- 駒を大きく押しつぶし（横1.22倍・縦0.74倍）、縦に弾んでから戻す。
- マスを白く光らせる。
- 衝撃の輪を2重に広げる（1.9倍と2.5倍）。
- 木くずのような光の粒を10個、四方に飛ばす。

光と輪は駒の下に描き、粒は駒の上に描く。光で駒の文字が隠れないようにするため。

### 盤全体の演出：揺れと波紋を両方入れた

いちばん意見が分かれた部分。試した順に並べる。

| 試したもの | 中身 | 評価 |
|---|---|---|
| 揺れ | 盤の枠を斜め下（縦4px・横±1.5px）に沈めながら少し縮め、跳ね返して揺れ戻す（220ms）。横に揺れる向きはランダム | 「気持ち悪い」と言われ、一度外した |
| なし | 盤は動かさない | 「つまらない」と言われた |
| 沈むだけ | 真下に2pxだけ沈んで戻る。横揺れも揺れ戻しもなし（140ms） | 「気持ち悪い」と言われた |
| 光の波紋 | 盤は動かさない。置いたマスを中心に、淡い光の輪が盤の端まで広がって消える（420ms） | 採用。コミットした |
| 揺れ（再評価） | 1行目と同じ揺れ。波紋は外した | 揺れだけで比べ直した |
| 揺れ＋光の波紋 | 両方を同時に出す | いったん採用（今の実装） |

分かったこと：

- 盤が動く演出は、動かし方を控えめにしても、それだけでは違和感が出やすい。
- 盤をまったく動かさないと、物足りない。
- 揺れと光の波紋を両方出す形で、いったん納得できた。揺れを単独で出すより良いかは、まだ評価の途中。

今後また調整するときは、揺れの量（`impact()` の `this.frame.animate`）と波紋の濃さ（`.board-ripple > div` の 0.55）から触るとよい。
