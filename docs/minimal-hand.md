# 攻方の持ち駒を最低限にする案の検証

2026-11-15 に検討した。**結論：案A（余りの駒を玉方に渡す）を採用候補とするが、現時点では実装しない。**

## 背景

問題データ（やねうら王 2020年クリスマスプレゼントの実戦詰将棋）は、コンピュータ同士の対局の終盤（元の対局で110手目前後）を切り出したものである。
そのため攻方の持ち駒が多く、王手を続けるだけで詰んでしまう問題が混ざる。

- 攻方の持ち駒は平均6.3〜6.4枚（中央値6枚）。10枚以上の問題が13〜16%ある（各手数20巻＝約2万問を集計）。
- 例：7手詰 577-171 は、攻方の持ち駒が「飛 角 金 銀2 桂2 香 歩7」の16枚。玉方は持ち駒なし。
- なお、データの読み込みの誤りではない。盤上の駒と持ち駒を合わせて全問40枚になることを、各手数3巻（約1万5千問）で確認した。

## 案

収録されている正解手順をたどり、攻方が最初に持っている必要がある最低限の持ち駒だけを残す。
手順の途中で取った駒を打つ分は、最初の持ち駒には数えない。余った駒の扱いで2案を比べた。

- **案A**：余りの駒を玉方の持ち駒に加える（作られた詰将棋の「残りの駒は玉方が持つ」流儀。盤と駒台で40枚のまま）
- **案B**：余りの駒を取り除く（盤と駒台で40枚未満になる。エンジンはこの局面も受け付ける）

どちらの案でも、検証で詰まなくなった局面は除く（または元の局面に戻す）前提である。

## 結果2：減らしても N 手で詰むか

`docs/minimal-hand/minhand-verify.mjs` で、各手数の321巻の先頭30問を調べた。
ブラウザと同じ WASM 版のエンジン（つようら王11mini、1スレッド、置換表16MB）で攻方の手番から3秒探索し、`score mate +k`（k ≤ N）が出た数を数えた。

| 手数 | 元のまま | 案A：余りを玉方に渡す | 案B：余りを取り除く |
|---|---|---|---|
| 3手詰 | 30/30（平均9ms） | 27/30（304ms） | 28/30（203ms） |
| 5手詰 | 30/30（68ms） | 27/30（236ms） | 28/30（136ms） |
| 7手詰 | 30/30（400ms） | 22/30（719ms） | 24/30（555ms） |
| 9手詰 | 28/30（1941ms） | 21/30（1656ms） | 22/30（1547ms） |
| 11手詰 | 25/30（2841ms） | 21/30（2616ms） | 24/30（2409ms） |

- 「元のまま」でも9・11手詰で取りこぼしがある。3秒の通常探索では長い詰みを見つけきれないためで、案A・B の数字にも同じ取りこぼしが含まれる。
- 残る割合はおおむね、3〜5手詰で約9割、7〜11手詰で約7〜8割。

## 分かったこと

- **収録されている手順は、玉方の応手を1通りだけたどった「本手順」である。**
  玉方が別の応手（変化）を選んだときは、本手順では使わない持ち駒が必要なことがある。
  例：3手詰 `l2+R3nl/2+S1g1k2/4+b1pP1/4p1Spp/Pp4N2/3+b1PG1P/1P2+r1P2/6S2/5GKNL w S2Pgnl5p 110`（解 `5g3g 4i4h 6f4h`）。
  本手順では駒を一度も打たないが、持ち駒を0枚にすると詰まなくなる。
  したがって、**案Bでも本手順だけから求めた持ち駒では足りないことがあり、どちらの案もエンジンでの検証が必要**。
- **案Aでは、玉方が受け取った駒で合駒できるようになる**ため、案Bより少し多く詰まなくなる。
  一方で、合駒を考える場面が増えるので、問題としては案Aのほうが面白くなると考えられる。
- **案Aでは、収録解がそのまま正解とは限らない**（玉方が合駒して別の手順になることがある）。
  最短解は、検証の探索でエンジンが出した読み筋に置き換える必要がある。
- **手数が N より短くなることはない。** 攻方の打てる駒は減り、玉方の受けの手段は増えるだけなので、「N 手以内の詰みが見つかった」ならちょうど N 手詰である。

## 実装する場合の選択肢

1. **出題時にアプリ内で変換する**：出題のたびに案Aの局面を作り、エンジンで1〜2秒探索して検証する。詰みが見つからなければ元の局面で出題する。
   データの作り直しも事前の一括処理も要らない。代わりに出題時に1〜2秒待ち、9・11手詰では元の局面に戻ることが多い。
2. **事前に一括変換して R2 のデータを差し替える**：手元の PC で、高速な普通のビルドのエンジンを全コアで回して検証し、残った問題と新しい解を保存する。
   出題時の待ちはない。ただし全500万問だと、1問0.5秒・10コアでも約70時間かかるので、一部の問題に絞る必要がある。
   長い手数の取りこぼしを減らすには、詰み専用の探索（やねうら王の詰将棋エンジンなど）を使うとよい。
3. **持ち駒の枚数で絞るだけ**：「攻方の持ち駒 N 枚以下」を出題設定に足す。最も簡単だが、「持ち駒は少ないのに簡単」な問題は残る。

## 再現手順

```bash
npm run fetch:problems                                   # 問題データを .cache/shogimate に取得
python3 docs/minimal-hand/minhand.py                     # 結果1
node docs/minimal-hand/minhand-verify.mjs "$PWD" 30 3000 # 結果2（10分前後）
SHOWFAIL=1 BOOKS=mate3 node docs/minimal-hand/minhand-verify.mjs "$PWD" 30 3000  # 詰まなかった局面を表示
```

📝 Node で Emscripten の pthread 版を動かすときは、待ち受け中もタイマーなどでイベントループを維持すること。
探索スレッド（worker）はイベントループを維持しないので、Node が探索の途中で終了してしまう（スクリプトでは `setInterval` で対処している）。
